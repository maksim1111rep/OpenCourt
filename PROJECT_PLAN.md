# 1 версия

### Система спортивных объектов
Владельцы (пока без разделения пользователей на разные сущности) добавляют свои
спортивные объекты в систему OpenCourt. Они указывают информацию о названии объекта,
городе объекта (свободным текстом), его адресе (тоже свободным текстом) (одинаковый
адрес допустим в данной версии), рабочих часах, телефон для бронирования корта
на объекте и, собственно, сами корты внутри объекта. Все данные обязательны, кроме
кортов. Центр и первоначально указанные корты должны создаваться целиком либо не 
создаваться вообще. Пользователь должен получить информацию о некорректных данных,
а не частичный результат. Владельцы также могут изменять информацию об объектах и 
кортах. Изменение может быть точечное в какой-то одной или нескольких частях
информации о площадке/корте. Объект удаляется вместе со всеми кортами. Корт может
быть удален из системы отдельно. Добавление корта производится изначально или
путем добавления по одному, когда объект уже добавлен. Вывод всех объектов
пагинируется и вывод производится страницами. Доступен поиск объекта по названию
или городу. Поиск проводится по частичному совпадению с запросом без ранжирования
и без учета регистра, отступов и пробелов. Поиск можно проводить одновременно по
названию и городу. Количество объектов на странице выбирает сам пользователь.
Максимум 100, по умолчанию 20. Сортируется по `id` по возрастанию.

##### Система рабочих часов
На 1 день есть 3 состояния: выходной, обычный рабочий день и круглосуточный.
Интервалы хранятся только в обычном рабочем дне. Хранится сколько угодно интервалов
на день, в разные дни может быть несколько разных интервалов, но они не могут
пересекаться или соприкасаться (начинаться и заканчиваться в одно время) между 
собой, часы целиком в одном дне, это именно рабочие часы площадки, а не доступное 
для бронирования время. Отсутствие дня при заполнении означает "выходной". 
При выставлении состояния "круглосуточно" все интервалы удаляются. При выставлении
"выходного" все интервалы удаляются. При удалении всех интервалов из рабочего дня
состояние переходит в "выходной"

### Корты
Корты имеют технические "названия" (порядок кортов в одном объекте "1.1", "1.2", 
"Центральный" или по усмотрению владельца, но обязательно уникальные (без учета
регистра, отступов, пробелов) названия) (непустое значение). Они добавляются внутрь
и живут только внутри объекта. Корты должны хранить свой тип (открытый, закрытый,
открытый, но под навесом) (может быть null), конфигурация (2 кольца, 1 кольцо)
(может быть не указан), материал поверхности (дерево, синтетическое покрытие, 
резина, асфальт, бетон, другое) (может быть не указан), освещение 
(присутствует/отсутствует) (может быть не указано), кольца (высота)
(может быть не указано), разметка (только баскетбольная, совмещенная с другими
спортами, только часть, отсутствует) (может быть не указано), фото корта (может
быть не указано).

##### Фотографии корта
Запрос передаётся в формате multipart/form-data, поскольку содержит
структурированные данные и файлы.
UI присваивает каждому ещё не сохранённому корту временный идентификатор. Он
используется только для сопоставления фотографий с кортами внутри формы и запроса.
Если данные центра, любого корта или любой фотографии некорректны, центр и корты
не создаются. Частичное сохранение недопустимо.
Один корт может содержать от 0 до 9 фотографий.
Разрешённые форматы: JPEG, PNG, WebP.
Максимальный размер одной фотографии — 5 МБ.
Ориентировочный максимальный размер общего запроса — 50 МБ.
Ограничения формата, размера и количества проверяются сервером, даже если они уже
проверены на UI.
Сервер не использует исходное имя файла для физического хранения. Для файла
создаётся уникальное внутреннее имя.
У записи фотографии в базе есть отдельный числовой идентификатор, автоматически
назначаемый базой данных. Он не определяет имя, принадлежность или порядок фотографии.
Файлы хранятся в отдельной локальной директории вне ресурсов и каталога сборки
приложения.
Информация, необходимая для поиска файла и его связи с кортом, хранится отдельно от
самого файла.
Фотографии одного корта имеют позиции, начинающиеся с 1 и идущие без пропусков.
Первая фотография считается главной.
Пользователь может изменять порядок фотографий. После перестановки главной
становится новая первая фотография, но физические файлы не переименовываются.
После удаления фотографии позиции оставшихся фотографий пересчитываются. Если
удалена главная фотография, главной становится следующая.
Для каждой загружаемой фотографии сервер генерирует уникальный случайный
идентификатор. Он используется во внутреннем имени файла и не изменяется в течение
жизни фотографии.

### Пользователи
Пользователи по умолчанию получают краткую информацию об объектах (название, город, 
адрес и рабочие часы) и получают полную информацию об объектах с кортами только при
отдельном запросе
